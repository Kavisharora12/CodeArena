# Overview
CodeArena is a platform for developers to practice coding and share solutions. It includes the **Monaco Editor**, progress tracking, Markdown-based solution posts, and an opt-in local Node.js child-process runner for JavaScript. The runner is suitable only for local development or trusted, limited environments, not arbitrary public submissions.

# API Documentation

## CodeArena problem discussions

Discussion data is stored in `problems/{problemId}/discussions/{discussionId}` with replies in each discussion's `comments` subcollection. Deploy the Firestore rules and composite indexes with `firebase deploy --only firestore` before using search or non-default sort modes.

| Method | Endpoint | Authentication | Description |
|---|---|---|---|
| `GET` | `/api/problem/{problemId}/discussions?sort=newest&q=search-text` | Public | List a bounded page of 20. Supports `sort=newest`, `upvoted`, or `discussed`, `q`, and a `cursor` returned by the previous response. |
| `POST` | `/api/problem/{problemId}/discussions` | Firebase session | Create a post. Body: `{ "title": "...", "content": "...", "tags": ["..."] }`. |
| `GET` | `/api/problem/{problemId}/discussions/{discussionId}` | Public | Read a discussion. |
| `PATCH` | `/api/problem/{problemId}/discussions/{discussionId}` | Firebase session; author or admin | Update title, content, and/or tags. |
| `DELETE` | `/api/problem/{problemId}/discussions/{discussionId}` | Firebase session; author or admin | Soft-delete a post, preserving its reply subcollection. |
| `GET` | `/api/problem/{problemId}/discussions/{discussionId}/comments` | Public | List a bounded page of 50 replies. |
| `POST` | `/api/problem/{problemId}/discussions/{discussionId}/comments` | Firebase session | Add a reply. Body: `{ "content": "...", "parentCommentId": null }`; `parentCommentId` may identify another reply. |
| `PATCH` | `/api/problem/{problemId}/discussions/{discussionId}/comments/{commentId}` | Firebase session; author or admin | Edit a reply. |
| `DELETE` | `/api/problem/{problemId}/discussions/{discussionId}/comments/{commentId}` | Firebase session; author or admin | Delete a reply, preserving it as a tombstone when it has replies. |
| `POST` | `/api/problem/{problemId}/discussions/{discussionId}/vote` | Firebase session | Toggle the current user's vote; no user ID is accepted from the client. |

Protected endpoints verify the Firebase session cookie and derive the author from that session. Firestore rules deny direct client writes; authorization is enforced by these server routes because Admin SDK requests bypass rules. Discussion content is Markdown and is rendered with raw HTML disabled.

## Endpoint: `/api/auth/sign-up`

### Description
This endpoint registers a new user. It performs the following actions:

- Checks if all required fields (`username`, `email`, `password`) are provided.
- Validates input using the `signUpValidation` schema.
- Checks if the email is already used by another user:
  - If used by a verified user, registration is blocked.
  - If used by an unverified user, the record is updated with the new username, password, and verification code.
- If the email is new, a new user is created with empty arrays for `solutions`, `submission`, and `solvedQuestions`.
- Generates a 6-digit verification code with 5-minute expiry.
- Hashes the password before storing it in the database.
- Sends a verification email containing the code using `sendVerificationEmail`.

### Method
`POST`

### Request Body

Send a JSON object with the following fields:

- `username`: A unique string (required)
- `email`: A valid email address (required)
- `password`: A string with a secure password (required)

#### Example Request
```json
{
  "username": "john_doe",
  "email": "john@example.com",
  "password": "securePassword123"
}
```

### Example Response
The response will be a JSON object with the following fields:

- `success` (boolean): Indicates whether the request was successful (`true`) or not (`false`).
- `message` (string): Provides additional information about the result. For example, success confirmation or error description.
- `userId` (string – MongoDB ObjectId): A unique identifier automatically generated by MongoDB for each user. It is used to distinguish one user from another in the database.


#### Success Response
```json
{
    "success": true,
    "message": "User registered successfully. Please verify your email",
    "userId": "7584752jfdkjfak..."
}
```

- Requires a valid JWT token with `userType: "admin"`.
- Checks for admin privileges. Only admin users can access this route.
- Connects to the database using `connectToDb`.
- Parses and validates the request body using the `createProblemValidation` schema.
- Automatically generates a unique **problem index** based on the current number of problems in the database.
- Checks if a problem with the same title already exists.
- If validation passes and the title is unique:
  - Creates a new problem document with the provided details.
  - Initializes empty arrays for `similarQuestions` and `solutions`.
- Returns a success response with the newly created problem’s ID.

- `topics` (string): Problem topics or tags, e.g., `"Array, Hash Table"` (required).

### JavaScript stdin contract

Run passes the custom input string to the program's `process.stdin` and captures `console.log`/stdout and stderr. Submit passes each stored Firestore `testCases[].input` string the same way; the corresponding `output` is the expected stdout. Solutions must read the raw stdin and print their answer. The runner does not infer function signatures or parse structured LeetCode parameters such as `nums = [...]` automatically. Grading converts CRLF/CR to LF and trims only outer whitespace; internal whitespace is significant.
## Endpoint: `/api/code/run-code`

### Description
Runs JavaScript in a restricted local Node.js child process against caller-supplied stdin. Requires a verified Firebase session. This is suitable only for local development and trusted limited environments, not public untrusted submissions.

### Method
`POST`

### Request Body

Send `problemId`, `sourceCode`, and `input`. Limits: source 64 KB, stdin 16 KB, output 64 KB combined, and execution time 2 seconds. Output comparison is not performed by Run.

Requires a valid Firebase session cookie. Success includes the actual `stdout`, `stderr`, execution status, runtime, exit code, and error (if any). Run never creates a submission or updates progress. Invalid requests return `400`, unauthenticated requests `401`, missing problems `404`, oversized requests `413`, and rate/concurrency limits `429`.

## Endpoint: `/api/code/submit-code`

### Description
Loads expected inputs and outputs from the problem's Firestore document, runs each case independently, then saves a submission for the authenticated Firebase UID. Client-supplied test cases and user IDs are ignored. Solved progress is updated idempotently only if every case passes.

### Method
`POST`

### Request Body

Send `problemId` and `sourceCode`. The response reports passed/total counts but does not return hidden test inputs or expected outputs. Grading normalizes CRLF/CR to LF and trims whitespace at the beginning/end only; internal whitespace remains significant. Memory usage is not measured and is stored as `null`.

Requires a valid Firebase session cookie. It runs each server-stored test case in a separate process, with at most 30 cases, and saves a submission owned by the verified session UID. Solved progress is updated idempotently only if every test case passes. Do not expose this local child-process runner to arbitrary public submissions.

The runner uses Node's permission model, an allowlisted child-process environment, temporary source files, per-run time/input/output caps, and in-process concurrency/rate limits. It requires Node.js 20.13+ or 22+ and refuses to run as root or in an elevated Windows session. It is not an OS sandbox: code still runs with the web application's OS account, the Node permission model is not a security boundary against exploits, outbound network access is not blocked, and in-memory limits do not coordinate between server instances. Do not expose this implementation to arbitrary public submissions.

## Endpoint: `/api/user/streak`

Returns the signed-in user's current activity streak using saved documents in `submissions`. Each UTC calendar day with one or more saved graded submissions counts as one activity day. An activity today or yesterday keeps the consecutive-day streak active; missing the previous day resets the current streak to zero. `Run` actions are not saved submissions and do not count.

## Endpoint: `/api/notifications`

`GET` requires a verified Firebase session and returns up to 50 published app-wide announcements. `POST` requires the same session and additionally verifies the caller's `userType` is `admin` from the Firestore user record; request fields are a title (3–120 characters) and message (3–2,000 characters). Announcements are stored in the `notifications` collection and Firestore client reads/writes remain denied; users access them through this authenticated API.
